Salesforce Developer Interview Q&A — Part 4: LWC, SOQL & DevOps

Updated August 2026  ·  Part 4 of 4  ·  25 questions
Salesforce Developer Interview Series (100 questions) Part 1: Apex & OOP Part 2: Triggers & Async Part 3: Testing & Security Part 4: LWC, SOQL & DevOps

The final part of the Developer series covers Lightning Web Components, query optimization, and the DevOps/deployment knowledge expected of a senior-level candidate.

Lightning Web Components

1.What is a Lightning Web Component (LWC)?

A UI component built on modern web standards (native Web Components, ES6+ JavaScript, HTML templates) that runs on the Lightning Component framework. LWC coexists with the older Aura framework and can interoperate with it, but is now Salesforce's recommended approach for new UI development.

2.What is the @wire decorator used for?

It declaratively binds a component property or function to a Salesforce data source (an Apex method or a Lightning Data Service adapter), automatically re-invoking the wire whenever its reactive parameters change, and handling the resulting data/error states.

3.What's the difference between @api, @track, and a plain property?

@api exposes a property/method publicly so a parent component can set it or call it. @track (rarely needed since W3C proxy-based reactivity became default) forces reactivity for mutations to fields of an object/array. A plain property is private and reactive automatically for primitive reassignment.

4.How do sibling LWCs communicate with each other?

Through a parent component that listens for a custom event dispatched by the child (child-to-parent), then passes data down via a property to the sibling (parent-to-child) — or, for unrelated components, via a Lightning Message Service channel for pub/sub-style messaging.

5.How does a child component notify a parent of an event?

The child creates and dispatches a CustomEvent (this.dispatchEvent(new CustomEvent('save', { detail: data }))). The parent listens for it in the template using onsave={handleSave} and receives the payload via event.detail.

6.What is Lightning Data Service (LDS) and why use it over Apex?

LDS (lightning/ui*Api wire adapters like getRecord, createRecord) provides shared record caching, offline-priming support, and automatic FLS/CRUD enforcement without writing any Apex — reducing server round trips and keeping the UI in sync across components using the same record.

7.When would you still write an Apex controller instead of using LDS?

When you need complex server-side logic (aggregations, joins across multiple objects, custom business rules) that a single-record LDS call can't express, or when performance requires batching several related lookups into one round trip.

8.What does @AuraEnabled(cacheable=true) do?

It marks an Apex method as safe for the Lightning Data Service client-side cache and usable with @wire. Cacheable methods must be read-only (no DML) so the platform can safely reuse cached results and refresh them via refreshApex.

SOQL & SOSL

9.What's the difference between SOQL and SOSL?

SOQL (Salesforce Object Query Language) queries one specific object type (with related object traversal) and is ideal when you know which object/fields you're targeting. SOSL (Salesforce Object Search Language) performs a full-text search across multiple objects and fields simultaneously, ideal for a global "search everywhere" experience.

10.What makes a SOQL query "selective," and why does it matter?

A selective query filters on an indexed field (standard indexed fields, custom fields marked External ID/Unique, or fields on which a custom index was requested) and returns a small fraction of the object's total records. Non-selective queries on very large objects risk a full table scan and can time out or trigger a QueryException.

11.How do you avoid the "too many SOQL queries" governor limit error?

Bulkify: query once outside loops using a collected Set of Ids, use relationship queries to pull parent/child data in a single SOQL statement instead of separate queries per relationship, and cache repeated lookups in a Map for the duration of the transaction.

12.What is a relationship query and how do parent-to-child and child-to-parent syntax differ?

Child-to-parent uses dot notation (SELECT Name, Account.Industry FROM Contact). Parent-to-child uses a nested subquery with the child relationship name (SELECT Name, (SELECT LastName FROM Contacts) FROM Account), since an Account can have many Contacts.

13.What is the difference between an aggregate query and a regular SOQL query?

An aggregate query uses functions like COUNT(), SUM(), AVG(), typically combined with GROUP BY, to return computed summary results (as AggregateResult records) rather than individual sObject records.

14.How do you use the Query Plan tool and why is it useful?

Available in Developer Console, it shows the execution plan Salesforce's optimizer chose for a given SOQL query — including which index (if any) is used and the estimated cost — helping you diagnose why a query is slow or non-selective before it becomes a production performance issue.

15.What is a custom index and when would you request one?

A database-level index on a custom field, requested via a Salesforce Support case (or self-service on certain field types), used when a field is frequently filtered on in large objects but isn't naturally indexed (unlike External ID or Unique fields, which are indexed automatically).

DevOps & Deployment

16.What is Salesforce DX and why was it introduced?

A source-driven development model and CLI toolchain (sf commands) that treats metadata as version-controlled source files rather than the org itself being the source of truth — enabling standard software practices like branching, pull requests, and CI/CD pipelines for Salesforce development.

17.What is a scratch org?

A temporary, fully-configurable Salesforce org created from a definition file (project-scratch-def.json), typically used per-feature-branch or per-developer for isolated development and testing, then discarded once the feature is deployed and merged.

18.What's the difference between Metadata API and Tooling API?

Metadata API deploys/retrieves org configuration (objects, fields, classes, flows) as XML for CI/CD and package deployment. Tooling API exposes a more granular, often SObject-like interface to individual metadata components — commonly used by IDEs/tools for things like real-time class editing or fetching a single Apex class's body.

19.What is a Second-Generation Managed Package (2GP)?

A source-driven packaging format that lets ISVs and internal teams version, namespace, and distribute metadata as an installable package built from version-controlled source, replacing the older org-dependent 1GP packaging workflow.

20.What is a CI/CD pipeline in a Salesforce context?

An automated workflow (e.g., via GitHub Actions, GitLab CI, Azure DevOps, or Copado/Gearset) that validates and deploys metadata changes automatically when code is merged — typically running Apex tests, static code analysis, and a metadata deployment to a target sandbox or production org without manual intervention.

21.What is the difference between a Change Set and a Metadata API deployment?

Change Sets are a point-and-click, org-to-org deployment mechanism with no version control, best for very simple, low-frequency deployments. Metadata API deployments (via the sf CLI or CI/CD tools) are source-controlled, repeatable, and scriptable, and are the recommended approach for professional development.

22.What is a "destructive change" in a Salesforce deployment?

A deployment package (destructiveChanges.xml) that removes metadata components (fields, classes, etc.) from an org, rather than adding or updating them. These require care since deleting a field can cause irreversible data loss if not planned carefully.

23.What is a validation-only deployment and why use one?

A deployment run with --dry-run (or "Check Only" in Setup) that executes all Apex tests and validates the metadata without actually committing the changes — used to confirm a deployment will succeed before doing it for real, especially useful ahead of a production release window.

24.What does "quick deploy" mean in Salesforce deployments?

After a validation-only deployment succeeds, its Apex test results are cached for a limited time; a subsequent real deployment of the exact same changeset can skip re-running tests (quick deploy), which meaningfully speeds up the production release when tests are slow.

25.How do you handle environment-specific configuration (e.g., a sandbox vs. production endpoint) across deployments?

Use Custom Metadata Types or Named Credentials scoped per environment rather than hardcoding values in Apex — Custom Metadata records can be deployed once and then updated per org without a new code deployment, and Named Credentials keep endpoint/auth details out of source entirely.
