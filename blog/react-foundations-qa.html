React Foundations Q&A

August 2026  ·  Original notes based on Next.js's React Foundations course

Notes from the introductory chapters of Next.js's React Foundations course: how the browser renders a page, how JavaScript can update it imperatively versus declaratively, and what React and Next.js each contribute on top of that foundation.

Rendering and Updating the UI

1.What does a browser actually do to turn HTML into a visible page?

The browser parses HTML and CSS into the DOM and CSSOM, combines them into a render tree, then computes layout and paints pixels. Understanding this pipeline explains why changing the DOM after load triggers the browser to redo some or all of that work.

2.What is the difference between imperative and declarative UI updates?

Imperative code tells the browser the exact steps to change the DOM — select an element, then mutate it. Declarative code describes what the UI should look like for a given state, and the framework figures out the steps needed to get there.

3.Why does manually updating the DOM with plain JavaScript get harder as an app grows?

Each direct DOM mutation is another place that has to stay in sync with the current state. As more elements depend on more pieces of state, the number of manual update paths grows faster than the app's actual complexity, making bugs from missed updates more likely.

React and Next.js

4.What problem does React solve that plain declarative HTML/CSS cannot on its own?

React lets a UI be described declaratively in JavaScript, with components that automatically re-render when their state or props change, so the browser's DOM diffing and updates are handled by the library instead of by hand-written imperative code.

5.What does Next.js add on top of React?

Next.js is a framework built on React that adds application-level concerns React itself does not define, such as file-based routing, server rendering strategies, and build tooling — letting a developer focus on components while the framework handles the surrounding structure.
