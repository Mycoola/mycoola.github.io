JavaScript Fundamentals Q&A

August 2026  ·  Original notes based on MDN Web Docs

A compact set of original study notes for the JavaScript language: values and types, expressions, control flow, functions, collections, objects, classes, strings, promises, and regular expressions. The MDN pages are the references; the questions and explanations below are written as practical reminders.

Language Foundations

1.What is JavaScript responsible for in a web application?

JavaScript supplies behavior and application logic. HTML describes structure, CSS describes presentation, and JavaScript can read or change both through the DOM, respond to events, communicate with services, and coordinate state changes in the browser.

2.What is the difference between a primitive value and an object?

Primitive values represent indivisible data such as strings, numbers, booleans, bigints, symbols, null, and undefined. Objects are collections of properties and behavior. This distinction affects identity, mutation, comparison, and how values are passed through code.

3.Why should expressions be kept easy to read?

An expression combines values, operators, and calls to produce a value. Dense expressions may be valid but hide precedence, coercion, or side effects. Clear grouping and descriptive intermediate variables make the intended result easier to review and test.

4.How should a developer choose between let, const, and var?

Prefer const when a binding will not be reassigned and let when it will. Both are block-scoped and make lifetime easier to reason about. var has older function-scoping and hoisting behavior, so it is usually reserved for maintaining legacy code.

5.Why are template literals useful?

Template literals make interpolated strings and multi-line text readable. They also support tagged templates, which let a function process the literal parts and inserted values for specialized tasks such as formatting or safe query construction.

Control Flow and Functions

6.When is an if/else chain a poor choice?

It becomes difficult to scan when many branches compare the same value or combine unrelated conditions. A switch, lookup object, or separate strategy function can make the cases and their default behavior more explicit. The best choice depends on whether the logic is data selection or complex computation.

7.What is the purpose of exception handling?

Exception handling separates expected recovery from the normal path. A try/catch block can translate a low-level failure into a useful application response, while finally can release resources. Catching errors without recording or handling them merely hides defects.

8.What makes a function a useful unit of design?

A function gives a behavior a name, input contract, and return contract. Small functions with focused responsibilities are easier to test and compose. They should make side effects obvious and avoid depending on mutable state that callers cannot see.

9.What is a closure?

A closure is a function together with access to variables from its surrounding lexical environment. Closures are useful for factories, callbacks, and private state, but long-lived closures can also retain objects longer than intended, so their lifetime matters.

10.How do loops and iteration differ conceptually?

A loop describes repeated control flow; iteration describes visiting values from an iterable. Use the simplest form that expresses the need: a classic loop for precise control, or an iterator and array method when the operation is naturally mapping, filtering, reducing, or searching.

Collections and Objects

11.When is an array the right collection?

Use an array for an ordered sequence whose items are naturally accessed or processed in order. Array methods such as map, filter, find, and reduce communicate intent, while direct index manipulation is appropriate when positional updates are the actual requirement.

12.What problem do Map and Set solve?

Map stores key-value associations with keys of any value type, while Set stores unique values. They are clearer than using an object as a general-purpose dictionary or an array for uniqueness checks, and they provide operations designed around their respective data models.

13.What is the difference between an object's property and its prototype?

A property belongs directly to an object or is resolved through its prototype chain. Prototypes allow objects to share behavior without copying every method onto each instance. Code should be explicit about ownership when checking or modifying properties.

14.When do classes improve JavaScript code?

Classes provide familiar syntax for constructing related objects, defining methods, and expressing inheritance. They help when a domain has stable instances and behavior; they do not automatically make a design better than functions and composition.

15.Why should string operations account for more than ASCII?

JavaScript strings use UTF-16 code units, so a visible character may occupy more than one code unit. Operations based only on indexes or length can therefore split or count some Unicode characters incorrectly. Use APIs appropriate to the text and locale requirements.

Asynchronous and Pattern-Based Code

16.What problem do promises solve?

A promise represents the eventual result or failure of an asynchronous operation. It lets code compose dependent work with then/catch/finally or async/await, keeping success and failure paths visible instead of nesting callbacks for every step.

17.Why should promise failures be handled deliberately?

An unhandled rejection can leave the UI or workflow in an incomplete state. Each asynchronous boundary should decide whether to recover, show a user-facing error, retry, or propagate the failure to a layer that owns the response.

18.What are regular expressions good at?

Regular expressions are useful for recognizing or extracting text patterns, such as a constrained token or a simple delimiter structure. They become fragile for nested or grammar-heavy formats, where a parser gives clearer rules and better error reporting.

19.How should errors be handled in reusable JavaScript code?

Define which failures are expected, preserve useful context, and expose a predictable contract to callers. Validate inputs at boundaries, use meaningful error types where helpful, and avoid returning a mixture of unrelated sentinel values and thrown exceptions for the same operation.

20.What is the broadest lesson from the JavaScript reference?

Choose language features according to the data and control flow you actually have. Clear scope, explicit state transitions, appropriate collections, and visible asynchronous boundaries make JavaScript easier to maintain than clever syntax used without a clear contract.
