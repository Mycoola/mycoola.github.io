Claude Code Q&A — Setup, Context, Hooks & the Agent SDK

August 2026  ·  Based on Anthropic's Claude 101 and "Claude Code in Action" courses, plus the official Claude Code docs

Notes from Anthropic's Claude 101 and Claude Code in Action courses, plus the official Claude Code docs. Covers going from a first Claude conversation to running longer, less-supervised Claude Code sessions with hooks and the Agent SDK.

Getting Started

1.What is Claude, at a basic level?

Claude is Anthropic's AI assistant — a large language model you converse with in natural language to get help with writing, research, analysis, and (via Claude Code) software development tasks.

2.What is Claude Code, and how is it different from asking Claude a question in a chat window?

Claude Code is an agentic coding tool: instead of just answering questions, it reads your actual codebase, edits files, runs terminal commands, and iterates — available in the terminal, VS Code, JetBrains, a desktop app, and the web, all sharing the same underlying engine.

3.What are the main ways to install Claude Code?

A native installer (curl script on macOS/Linux/WSL, PowerShell on Windows), Homebrew ( brew install --cask claude-code), WinGet, or Linux package managers (apt/dnf/apk) — native installs auto-update in the background, while Homebrew and WinGet require a manual upgrade command.

4.What is involved in "project setup" before using Claude Code on a repo?

Making sure Claude Code can orient itself in the project — this includes having a clean git state, relevant docs available, and optionally a CLAUDE.md file with project-specific conventions so Claude behaves consistently across sessions.

Working With Claude Code Day-to-Day

5.How does Claude Code actually make changes to a codebase?

It plans an approach, edits files directly, and shows you the diff — you review the change and can ask for adjustments before accepting, similar to reviewing a colleague's pull request rather than writing the code yourself line by line.

6.What does "controlling context" mean in a Claude Code session, and why does it matter for long sessions?

It means scoping what Claude works on (e.g., with plan mode) and managing how conversation history is compacted as a session runs long, so summaries retain what matters instead of losing important earlier decisions as the context window fills up.

7.What's the practical difference between "adding context" and "controlling context"?

Adding context is proactively giving Claude Code the right inputs (files, docs, instructions) up front for a specific task; controlling context is managing the accumulated conversation/session state over time so a long-running session stays focused and doesn't drift.

8.What are custom commands (skills) in Claude Code, and when should you create one?

Custom commands package a repeated procedure — like /review-pr or /deploy-staging — into a reusable, on-demand action. Create one whenever you find yourself typing the same multi-step instructions to Claude Code repeatedly.

Extending Claude Code: MCP, Hooks & GitHub

9.What is MCP, and why would you connect an MCP server to Claude Code?

The Model Context Protocol is an open standard for connecting AI tools to external data sources and systems — connecting an MCP server lets Claude Code read design docs, update tickets, pull chat history, or call custom internal tooling directly from a session.

10.What is a Claude Code hook, and what problem does it solve?

A hook is a shell command that runs automatically before or after a Claude Code action (like a file edit) to enforce a rule that must never be skipped — for example, auto-formatting after every edit or blocking a commit until tests pass.

11.How does a hook actually control whether Claude Code's action is allowed to proceed?

Hooks communicate back to Claude Code via a permission-decision JSON payload and process exit codes — a non-zero exit (or a "deny" decision) blocks the action and can feed an explanation back into the loop so Claude can self-correct.

12.What's a good first hook to implement, and why?

A verification hook that checks Claude's own work — e.g., running the test suite or a linter after an edit — because it directly demonstrates the value of hooks: catching problems automatically instead of relying on a human to remember to check.

13.What's a common "gotcha" to watch for when writing Claude Code hooks?

Hooks that are too aggressive or too slow can block legitimate work or make sessions feel unusable — it's easy to over-constrain a hook (denying too much) or under-constrain it (allowing the exact thing it was meant to prevent) if the trigger conditions aren't tested carefully.

14.What does Claude Code's GitHub integration let you automate?

The managed GitHub Action wires Claude into pull requests for automated code review and can respond to issues or PR comments, letting review feedback happen without a human manually invoking Claude Code each time.

Going Further: The Agent SDK

15.What is the Claude Code Agent SDK, and who is it for?

It's a toolkit for developers who want to build fully custom agents powered by Claude Code's underlying tools and permission model, rather than using the CLI/IDE surfaces directly — useful when you need a bespoke agent embedded in your own product or pipeline.

16.Why would a team choose to build on the Agent SDK instead of just scripting the Claude Code CLI?

The SDK exposes finer-grained control over orchestration, tool access, and permissions than shelling out to the CLI, which matters when an agent needs to be embedded in a larger automated system rather than run interactively by a human.

17.What are the different surfaces Claude Code can run on, and why does that matter?

Terminal, VS Code, JetBrains, a standalone desktop app, and the web — all sharing the same engine, so a project's CLAUDE.md, settings, and MCP servers work identically no matter which surface a session runs on, letting you move a task from your laptop to your phone mid-session.

18.What's the VS Code extension specifically good for that the CLI alone isn't?

It surfaces Claude Code inline in the editor — inline diffs, @-mentions of files, plan review, and conversation history — so you can review and steer changes visually instead of reading a terminal transcript.

19.How would you summarize the overall skill progression this course content teaches, from "Claude 101" to "Claude Code in Action"?

Start with basic conversational use of Claude (101), then move to using Claude Code for real edits on a real repo, then to controlling and extending long sessions with context management and hooks, and finally to building fully custom agents on the SDK for unattended, automated workflows.

20.Why does Anthropic include a knowledge-check quiz partway through the "Claude Code in Action" course?

To reinforce the setup/context/making-changes fundamentals before introducing hooks and the SDK — those later, more powerful features assume you're already comfortable with the basic edit-review-iterate loop.
