Salesforce Developer Interview Q&A — Part 3: Testing, Integrations & Security

Updated August 2026  ·  Part 3 of 4  ·  25 questions
Salesforce Developer Interview Series (100 questions) Part 1: Apex & OOP Part 2: Triggers & Async Part 3: Testing & Security Part 4: LWC, SOQL & DevOps

This part covers Apex testing methodology, integration testing/mocking, and the secure coding practices interviewers expect from a mid-to-senior developer.

Apex Testing

1.What is the minimum code coverage required to deploy to production?

75% overall organization code coverage, and every trigger must have some coverage (technically >0%, though 75%+ per class is the practical target). Coverage is a compliance metric, not a quality metric — 75% coverage with weak assertions proves far less than 60% coverage with strong ones.

2.What is @isTest and how is it used?

An annotation marking a class or method as test-only code. Test classes/methods don't count toward the org's Apex code size limit and can't be called from non-test contexts. Test methods must also include the @isTest annotation (or legacy testMethod keyword) individually.

3.What is Test.startTest() / Test.stopTest() used for?

They reset governor limits for the code executed between them, and force any asynchronous Apex enqueued inside the block (Future, Queueable, Batch start) to execute synchronously before stopTest() returns — allowing you to assert on the results of async operations within the same test method.

4.Why should test classes never rely on existing org data?

Tests run against a fresh, isolated data context by default (no access to existing records unless @isTest(SeeAllData=true) is used, which is discouraged) so they are deterministic and portable — they need to pass identically in every sandbox, scratch org, and the production org itself.

5.What is a Test Data Factory pattern?

A utility class with static methods that generate consistent, valid test sObjects (e.g., TestDataFactory.createAccount()), reducing duplicated setup code across test classes and centralizing the definition of "what a valid test Account looks like" in one place.

6.How do you test bulk behavior in Apex?

Insert 200+ records (matching Salesforce's default trigger batch size) in your test setup and invoke the logic against that full collection, not a single record — this is the only way to catch a SOQL/DML-in-a-loop bug before it reaches production.

7.What is System.runAs() used for?

It executes a block of test code in the context of a specific user, letting you test sharing-rule enforcement, profile-based field visibility, or record ownership logic — since by default all test code runs as the System Administrator running the test, regardless of the calling user's actual profile.

8.What makes a good assertion in a test method?

Assertions should check specific expected values (System.assertEquals(expected, actual)) rather than just that "no exception was thrown." A test with zero assertions can pass 100% of the time while validating nothing — reviewers specifically look for this.

Integration Testing & Mocking

9.Why can't you make a real HTTP callout in a test method?

Salesforce disallows real outbound callouts during test execution to keep tests fast, deterministic, and independent of external system availability. Attempting one throws a CalloutException.

10.What is HttpCalloutMock?

An interface you implement to return a fake, predictable HttpResponse for any outbound REST callout during a test, registered via Test.setMock(HttpCalloutMock.class, new MyMock()). This lets you test callout logic including error handling without hitting a real endpoint.

11.What is WebServiceMock used for?

The equivalent of HttpCalloutMock for SOAP-based callouts generated from a WSDL — it lets you fake the SOAP response object structure so SOAP integration logic can be unit tested without a live external service.

12.How should you test error handling in an integration?

Write mocks that return each realistic failure mode you expect (400, 401, 404, 500, timeout, malformed JSON) and assert your code handles each gracefully — logging the error, retrying if appropriate, and not leaving the transaction in an inconsistent state.

13.What's the difference between a synchronous and asynchronous integration pattern?

Synchronous: the calling process waits for the external system's response before continuing (e.g., a real-time REST callout during a page load). Asynchronous: the request is fired and the response is handled later — via callback, polling, Platform Events, or Change Data Capture — decoupling the two systems' availability and latency.

14.What is idempotency and why does it matter in integrations?

An idempotent operation produces the same result no matter how many times it's executed with the same input — critical for integrations because network failures can cause retries, and without idempotency (e.g., using an external Id as an upsert key) a retry could create duplicate records.

Security & Secure Coding

15.What is CRUD and FLS enforcement, and why does it matter?

CRUD (Create/Read/Update/Delete) and FLS (Field-Level Security) enforcement ensures Apex code respects the running user's object and field permissions rather than silently exposing or modifying data they shouldn't have access to. This matters most in classes running without sharing or in @AuraEnabled methods exposed to the UI.

16.How do you enforce FLS/CRUD checks in Apex?

Use WITH SECURITY_ENFORCED in SOQL (or the newer WITH USER_MODE clause), the Security.stripInaccessible() method, or explicit Schema.sObjectType.Account.isAccessible()/isCreateable()/isUpdateable() checks before performing DML on user-supplied data.

17.What is SOQL injection and how do you prevent it?

SOQL injection occurs when unsanitized user input is concatenated directly into a dynamic SOQL string, allowing an attacker to alter the query's logic. Prevent it using bind variables (:variable) in static SOQL, or String.escapeSingleQuotes() combined with strict type-checking for dynamic SOQL.

18.What is Cross-Site Scripting (XSS) and how does Salesforce guard against it?

XSS occurs when unsanitized user input is rendered as executable script in a browser. Lightning Web Components auto-escape data bound in templates by default; Visualforce requires explicit use of HTMLENCODE()/JSENCODE() when outputting user-controlled data to avoid it.

19.What is Cross-Site Request Forgery (CSRF) and how is it mitigated on the platform?

CSRF tricks an authenticated user's browser into submitting an unwanted request. Salesforce mitigates this at the platform level (session tokens, referrer checks) for standard UI interactions, but custom REST endpoints exposed via @RestResource should still validate the caller via OAuth scopes rather than relying on cookies alone.

20.What is the principle of least privilege and how does it apply to Apex?

Grant only the minimum access needed to perform a task. In Apex, this means preferring with sharing by default, only using without sharing when a specific system-context need is justified and documented, and scoping Connected App OAuth scopes narrowly.

21.How do you securely store an API key or secret used by Apex?

Never hardcode secrets in Apex source. Use a Named Credential (or External Credential with the newer authentication provider framework) so the secret is stored encrypted by the platform and never appears in code, logs, or debug output.

22.What is a Named Credential and why is it preferred over storing endpoint/auth details in Custom Settings?

A Named Credential centralizes an external endpoint URL and its authentication (Basic, OAuth 2.0, JWT, certificate) in one encrypted, admin-managed record. Apex references it by name and never handles raw credentials, unlike storing a password in a Custom Setting/Metadata field which is visible to anyone with access to view that record.

23.What is the difference between authentication and authorization?

Authentication verifies who the caller is (login, OAuth token validation). Authorization determines what that verified caller is allowed to do (profile, permission set, sharing rules). A system can authenticate a user correctly and still incorrectly authorize them if permissions are misconfigured.

24.What is a common vulnerability in @AuraEnabled methods and how do you prevent it?

Exposing a method that performs DML/queries without CRUD/FLS enforcement, effectively letting any user who can access the component perform actions beyond their permission level. Prevention: explicitly enforce object/field-level security inside the method, and mark methods @AuraEnabled(cacheable=true) only for read-only, side-effect-free queries.

25.How do you test that sharing rules are correctly enforced?

Write a test using System.runAs() with a test user assigned a specific profile and role, insert records owned by a different user, and assert the test user can/cannot see or modify them as expected based on the org's sharing model.
