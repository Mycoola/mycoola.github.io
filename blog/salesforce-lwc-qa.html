Lightning Web Components Q&A

August 2026  ·  Original notes based on Salesforce developer documentation

Notes on Lightning Web Components (LWC): what they are, how they compare to Aura and Visualforce, and the core patterns for building and testing them.

1.Why did Salesforce introduce LWC alongside Aura instead of replacing it outright?

LWC is built on native web standards (Web Components, ES6+) and interoperates with existing Aura components, letting orgs adopt it incrementally in new components while keeping working Aura components running rather than forcing an all-or-nothing rewrite.

2.What is the role of the meta.xml configuration file in an LWC bundle?

It declares where a component can be used (record pages, app pages, Flow screens, etc.), its exposed properties, and API version — the platform-facing contract that determines how and where the component appears in the builder tools.

3.What is the difference between a public property and a getter in an LWC's JavaScript file?

A public (`@api`) property is set directly by a parent component or the page. A getter computes a derived value from other reactive state each time it's accessed — useful for formatted or combined values that shouldn't be stored redundantly.

4.Why does Lightning Web Components: Open Source matter for developers outside Salesforce orgs?

The open-source LWC engine lets developers build and run LWC-style components outside a Salesforce org entirely, which both broadens the skill's applicability and helps clarify which parts of LWC are platform-specific versus general web standards.

5.What should a component's tests focus on, beyond just "does it render"?

Good LWC tests should verify behavior in response to user interaction and prop/state changes — button clicks triggering the right event, computed getters updating correctly — not just that the markup exists in the DOM.

6.Why does choosing "Lightning Web Components or Aura" still come up as a real decision?

Some legacy functionality and certain older UI extension points remain Aura-specific, so a team maintaining an established org may still need Aura knowledge even while defaulting to LWC for all new development.
