Apex Language & OOP Fundamentals

1.What is Apex and how is it different from Java?

Apex is a strongly-typed, object-oriented programming language that runs natively on the Salesforce platform. It's syntactically similar to Java, but it's tightly coupled to the database — DML and SOQL are first-class language constructs — and it runs in a multi-tenant environment enforced by governor limits, which Java does not have.

2.What are governor limits and why do they exist?

Governor limits are runtime constraints Salesforce enforces per transaction (e.g., SOQL query count, DML statements, heap size, CPU time) to prevent any single tenant from monopolizing shared platform resources in a multi-tenant environment. Exceeding one throws a runtime exception that cannot be caught in the same context that triggered it.

3.What's the difference between a class and an interface in Apex?

A class defines both structure and behavior — fields, methods, and their implementations. An interface only declares method signatures without implementation; any class that implements the interface must provide the actual logic. Interfaces enable polymorphism and decoupling.

4.Explain the difference between abstract classes and interfaces.

An abstract class can contain both implemented and unimplemented (abstract) methods, and can hold state via member variables. An interface cannot implement any method body or hold instance state. A class can extend only one abstract class but implement multiple interfaces.

5.What access modifiers are available in Apex?

private (default, visible only within the defining class), protected (visible to the defining class and its subclasses), public (visible within the application/namespace), and global (visible everywhere, including managed packages — requires careful versioning since global members can't be removed later).

6.What is the difference between with sharing and without sharing?

with sharing enforces the running user's record-level sharing rules on all queries and DML within the class. without sharing executes in system context, bypassing sharing rules (though field-level security and CRUD permissions may still apply depending on how the class is written). Classes without an explicit sharing keyword inherit the sharing mode of the calling context.

7.What is polymorphism and how does it apply in Apex?

Polymorphism lets a variable of a parent type or interface reference an object of a subtype, and the correct overridden method is invoked at runtime. In Apex this is achieved through interfaces and virtual/override method inheritance, commonly used to swap implementations (e.g., different payment gateway integrations behind a common interface).

8.What's the difference between static and instance methods/variables?

Static members belong to the class itself and are shared across all instances within a single transaction — they reset between transactions. Instance members belong to a specific object and hold state unique to that object. Static variables are commonly used to prevent recursive trigger execution within a transaction.

9.What collection types does Apex support, and when would you use each?

List — ordered, allows duplicates, indexed access; use for ordered result sets. Set — unordered, no duplicates; ideal for uniqueness checks like collecting distinct Ids. Map — key-value pairs; ideal for fast lookups, commonly Map<Id, SObject> to avoid repeated queries inside loops.

10.What is an SObject and how does it differ from a regular Apex class?

An SObject is any object that can be stored and retrieved from the Salesforce database (standard like Account, or custom ending in __c). It automatically has fields, relationships, and DML/SOQL support built in, unlike a plain Apex class which has none of that unless explicitly coded.

11.What is the difference between an Apex Trigger and an Apex Class?

A trigger is Apex code that executes automatically in response to a DML event (before/after insert, update, delete, undelete) on a specific object. A class is a reusable code container that must be explicitly invoked — from a trigger, controller, batch job, or another class. Best practice is to keep triggers thin and delegate logic to handler classes.

12.What is a Design Pattern you commonly use in Apex, and why?

The Trigger Handler pattern (one trigger per object delegating to a handler class) keeps logic testable and centrally controlled. The Selector pattern centralizes SOQL queries per object. The Service layer pattern separates business logic from data access, improving reuse and testability across UI, API, and batch entry points.

13.What's the difference between == and .equals() in Apex?

For primitive types like Integer and String, == compares values. For sObjects and custom objects, == compares by reference unless equals()/hashCode() is overridden. In practice, Apex's == on sObjects actually performs a field-value comparison, unlike Java, which is a common trip-up point in interviews.

14.What is a Custom Exception and when should you create one?

A custom exception is a class that extends Exception, allowing you to define domain-specific error types (e.g., InvalidDiscountException). Create one when you need callers to differentiate your business-logic failures from generic runtime errors and handle them distinctly with targeted catch blocks.

15.What is the transaction boundary in Apex?

A transaction is the full unit of work — from the triggering event (a save, an API call, a scheduled job execution) through every trigger, flow, and Apex invoked as a result — that either commits entirely or rolls back entirely on an unhandled exception. Governor limits reset per transaction, not per method call.

16.What's the difference between a Formula field and a Roll-Up Summary field?

A formula field calculates a value on the same object (or across a lookup) in real time when read, using fields on that record or its parents. A Roll-Up Summary field aggregates (SUM, COUNT, MIN, MAX) child record values onto a master record, and only works across Master-Detail relationships, not standard Lookups.

17.What is the difference between a Lookup and a Master-Detail relationship?

A Lookup relationship loosely links two objects — the child can exist independently, and deleting the parent doesn't delete children by default. Master-Detail creates a tight ownership relationship — deleting the parent cascades to delete children, the child inherits the parent's sharing and security, and Roll-Up Summary fields are only possible on this relationship type.

18.What are the main data types in Apex?

Primitives (Integer, Double, Long, Boolean, String, Date, Datetime, Id), collections (List, Set, Map), sObjects, enums, and user-defined classes/interfaces.

19.What is an Enum in Apex and when would you use one?

An Enum defines a fixed set of named constants (e.g., OrderStatus { NEW, PROCESSING, SHIPPED }). Use it instead of raw strings to get compile-time safety, avoid typos, and make switch-style logic (using Apex's switch on statement) more readable.

20.What is a Wrapper class and why is it useful?

A Wrapper class combines fields from one or more sObjects (or computed values) into a single custom object, typically to pass structured, UI-friendly data between Apex and Visualforce/LWC — for example, wrapping a Contact with a computed "isSelected" checkbox flag for a table with row selection.

21.What is the difference between synchronous and asynchronous Apex at a conceptual level?

Synchronous Apex executes immediately within the calling transaction and shares its governor limits (e.g., a trigger or a button click). Asynchronous Apex (Future, Queueable, Batch, Scheduled) runs in a separate transaction with its own, generally higher, limits — useful for long-running or bulk operations that would otherwise exceed synchronous limits.

22.What is the difference between public and global in the context of managed packages?

public members are visible only within the same namespace/application. global members are exposed outside the package's namespace and, once released in a managed package, can never be removed or have their signature changed without breaking subscribers — so global should be used sparingly and deliberately.

23.What is method overloading, and does Apex support it?

Method overloading means defining multiple methods with the same name but different parameter lists (number, type, or order) within the same class. Apex supports this fully — the compiler resolves which version to call based on the arguments passed at compile time.

24.Can Apex classes be inherited? Explain class inheritance.

Yes — a class marked virtual or abstract can be extended by a subclass using extends. The subclass inherits public/protected members and can override virtual methods using the override keyword. Apex supports single inheritance only (no multiple class inheritance), though multiple interface implementation is allowed.

25.What is the purpose of the this keyword in Apex?

this refers to the current instance of the class. It's most commonly used to disambiguate between a constructor parameter and an instance field with the same name (e.g., this.name = name;), or to pass the current object as an argument to another method.
