Salesforce OmniStudio Q&A

August 2026  ·  Original notes based on Salesforce Help documentation

Notes on OmniStudio (formerly Vlocity): its component model, and how it compares to building the same functionality with custom Salesforce development.

1.What is the core value proposition of OmniStudio versus building equivalent functionality in custom Apex and LWC?

OmniStudio provides a declarative toolkit (OmniScripts, FlexCards, Integration Procedures) for building guided processes and UI without extensive custom code, trading some flexibility for faster configuration and easier maintenance by admins/architects rather than developers.

2.What is an OmniScript, at a conceptual level?

An OmniScript is a configurable, multi-step guided process (similar in spirit to a screen flow) that can call Integration Procedures and Data Mappers to orchestrate complex business processes through a step-by-step UI.

3.What problem does an Integration Procedure solve that an OmniScript alone doesn't?

Integration Procedures handle server-side orchestration — calling Data Mappers, Apex actions, and external services — separately from the UI-focused OmniScript, keeping data orchestration logic reusable across multiple OmniScripts or FlexCards.

4.Why does knowing which OmniStudio version an org has matter before building new components?

OmniStudio has evolved through different packaging and licensing models (managed package vs. Core platform features), and available capabilities/UI can differ meaningfully between versions — building against the wrong assumptions can produce components that don't work as expected.

5.How does a FlexCard integrate with Knowledge or other data sources?

A FlexCard's data source configuration typically points to an Integration Procedure or Data Mapper that retrieves the underlying records (including Knowledge articles), letting the card render live data without embedding query logic directly in the card's display configuration.
