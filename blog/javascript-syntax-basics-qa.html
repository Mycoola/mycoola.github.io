JavaScript Syntax Basics Q&A

August 2026  ·  Original notes based on W3Schools

Foundational notes on JavaScript syntax: how statements are written, how output is produced, how variables and comments work, and how the built-in array sort method behaves — a set of basics that everything else in the language builds on.

Statements, Syntax, and Output

1.What is a JavaScript statement, and why does statement order matter?

A statement is an instruction executed by the browser or runtime, and statements normally execute in the order they are written, top to bottom. Understanding that sequence is what makes it possible to predict a script's behavior before running it.

2.Why do consistent syntax conventions matter even though JavaScript is often forgiving?

JavaScript tolerates some inconsistency, such as optional semicolons in many cases, but relying on that tolerance makes code harder to read and more prone to subtle bugs. Consistent formatting communicates intent and reduces the chance of a parser interpreting a line differently than expected.

3.What are the different ways a script can produce output, and why does the choice matter?

Output can go to an element's content, a dialog, the console, or be written directly into the document during parsing. Console output is best for debugging; user-facing output belongs in the page itself, so mixing the two approaches in production code creates a poor experience.

Comments and Variables

4.What is the purpose of a comment that just restates the code below it?

A comment that repeats what a line already shows adds noise rather than value. Useful comments explain why a decision was made or clarify a non-obvious constraint, not what a simple statement is already doing.

5.Why is declaring a variable before using it a good habit, even though JavaScript sometimes allows undeclared assignment?

An explicit declaration states the variable's scope and existence up front, which prevents accidental globals and makes it clear to a reader (and to strict-mode checks) that the variable is intentional rather than a typo.

Arrays

6.What does Array.prototype.sort do by default, and why does that surprise people sorting numbers?

By default, sort converts elements to strings and compares them in Unicode order, so numeric values sort as text unless a comparison function is supplied. Sorting `[10, 1, 2]` without a comparator gives `[1, 10, 2]`, not the numeric order most people expect.

7.How does a comparison function change sort's behavior?

Passing a function such as `(a, b) => a - b` tells sort to use the function's return value to decide order: negative means a comes first, positive means b comes first, and zero means their order is left unchanged relative to each other. This makes numeric and custom ordering possible.

8.Why does it matter that sort mutates the original array?

sort reorders the array in place and also returns it, so code that needs to preserve the original order elsewhere must copy the array first. Relying on the return value alone while ignoring the mutation can introduce bugs where a shared array changes unexpectedly.
